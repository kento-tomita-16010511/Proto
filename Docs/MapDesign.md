# マップ設計書 — 廃病院マップ(1フロア)

本書は「リアルで現実味のある建物・マップを作るための方法」(設計資料画像)を本プロジェクト向けに明文化した設計書です。
Claude Code / Codex CLI のどちらで作業する場合も、マップ生成・調整は必ず本書を正として行うこと。
実装(`Assets/Scripts/Tool/Editor/MapGenerator/HospitalMapLayoutUtility.cs` のレイアウト表)と本書は**必ず1対1で同期**させること。

---

## 1. 設計原則(資料画像より)

### 1-1. 「建物を作れ」ではなく「実在する建築の考え方を真似して作れ」

実在する病院の設計を参考に、骨格(フレーム)を先に作る。部屋は骨格に沿って配置する。

- 中央ホール / ナースステーション / 搬送ルート / 非常階段 / サービス通路 / 設備室 / バックヤード

### 1-2. 「距離が狭い」への対処

箱を並べるだけの配置にせず、「体験(動線・視線・距離感)」を設計する。
受付 → 待合(広い空間) → 長い廊下・ホール → 診察室・検査室・薬局 の順に体験が流れる構成にする。

### 1-3. 廊下を先に設計する

まず廊下だけを設計することで、自然な距離や空間のリズムを生む。

| 条件 | 規定値 |
|---|---|
| 廊下幅 | 3m(1グリッド) |
| 中央ホール | 12m × 12m(4×4グリッド) |
| 総延長 | 100m 以上 |
| 形状 | L字・T字・十字路を含む |
| 構造 | 回廊(ループ)を含む |

### 1-4. スパン(グリッド)で指定する

**3mグリッド**を基準に部屋の大きさをスパンで指定する(Unityでの実装がしやすい)。

| 部屋 | スパン | 実寸 |
|---|---|---|
| 受付 | 4×5 | 12m × 15m |
| 診察室 | 4×4 | 12m × 12m |
| 病室(大部屋) | 4×4〜5×5 | 12〜15m 四方 |
| 中央ホール | 4×4 | 12m × 12m |

### 1-5. 禁止事項(AIに明示する・効果大)

- 正方形だけの建物
- 一直線の廊下
- 全部同じ大きさの部屋
- 左右対称
- 部屋を敷き詰める設計
- **部屋同士が直接つながるだけの設計(部屋の出入りは必ず廊下・ホール経由)**
- ゲームマップ感のある構造

### 1-6. ホラー演出に適した空間・動線設計

- 長い廊下・遠くまで見える視線(10〜20m先まで見える廊下)
- 角を曲がるたびに視界が切り替わる
- 広い空間と狭い通路のメリハリ
- 遠くに見える場所へ時間をかけて到達
- 近道に見えて遠回りになる動線
- ループ構造・回遊動線(同じ場所に戻ってくる不安感)

## 2. 確定レイアウト

座標系: 1グリッド = 3m。`RectInt(x, z, 幅, 高さ)`。x は東方向、z は北方向。
セル (x, z) のワールド座標範囲は `(x*3, z*3)〜(x*3+3, z*3+3)`。

### 2-1. 廊下骨格(先に設計)

| 名称 | RectInt | 特徴 |
|---|---|---|
| 玄関廊下 | (13, 2, 1, 8) | 南端 (13,2) が玄関(建物入口) |
| 中央ホール | (12, 10, 4, 4) | 12×12m の広い空間(吹き抜け想定) |
| 西廊下 | (4, 11, 8, 1) | 西端 (4,11) で **T字路** を形成 |
| 西翼北廊下 | (4, 12, 1, 7) | 管理エリアへ。北端は非常階段 |
| サービス廊下 | (4, 5, 1, 6) | 搬入口・機械室・霊安室へ |
| 東廊下 | (16, 12, 12, 1) | 診察エリアの幹線。東端 (27,12) で **L字** |
| 東翼廊下 | (27, 13, 1, 6) | 病室エリアへ北上 |

- **回廊(ループ)**: 中央ホール → 東廊下 → 東翼廊下 → 北廊下 → 中央北廊下 → 中央ホール

## 3. 生成のルール

### 3-1. 決定論とランダム性

- 廊下骨格・部屋の位置は**固定**(本書の表が正)。リアリティは人間の設計で担保する
- ランダム性は**ディテールのみ**: 各部屋のドア位置(廊下に面した辺からシード付き乱数で選択)
- 乱数は `HospitalMapConfigModel` の `RandomSeed` で決まる。**同じシードなら毎回同じマップ**が生成される

### 3-2. ドア(開口部)のルール

- 部屋のドアは**必ず廊下・ホールに面した辺**に1箇所生成する
- 部屋同士を直接つなぐドアは禁止(禁止事項 1-5 参照)
- 玄関は玄関廊下の南端 (13,2) の南辺に固定で生成する

### 3-3. 壁のルール

- 異なるゾーン(部屋↔廊下、部屋↔部屋、屋内↔屋外)の境界すべてに壁を生成する
- 廊下セル同士の境界には壁を生成しない(交差点・ホールは開放)
- 壁の高さ: 3m

## 4. Unityでの使い方

エディタメニュー **Tools > Hospital Map Generator** を開き、上から順に実行する。

1. **設定アセットを作成** — `Assets/ScriptableObjects/Map/HospitalMapConfig.asset` を作成(既存があれば読み込み)
2. **仮Prefabを生成して割り当て** — `Assets/Prefab/Map/Placeholder/` に床・壁・ドア・天井の仮Prefabを生成し、設定に割り当てる
3. **レイアウトを検証** — 重複・廊下未接続・分断・総延長不足をチェックする
4. **マップを生成** — シーンに `HospitalMap` ルートを生成する(既存の `HospitalMap` は削除して再生成)。「Terrainを非アクティブ化」をONにすると既存Terrainを無効化する
5. **NavMeshを再ベイク** — シーン内の `NavMeshSurface` を使って再ベイクする(敵のNavMesh移動を維持するため生成後は必須)

### Prefab差し替え

見た目のクオリティアップは `HospitalMapConfig.asset` の床・壁・ドア・天井Prefab参照を
本番アセットに差し替えて再生成するだけでよい(生成ロジックの変更は不要)。
Prefabの規格: 床=3m×3m(原点が床面中央)、壁=幅3m×高さ3m(原点が下端中央)、ドア=壁と同規格で開口部つき。

## 5. レイアウト変更時の手順(Claude / Codex 共通)

1. 本書 2-1 / 2-2 の表を更新する
2. `HospitalMapLayoutUtility.cs` のレイアウト表を同じ値に更新する
3. ツールの「レイアウトを検証」を実行しエラーが無いことを確認する
4. 1-5 の禁止事項に反していないか目視確認する(ASCIIマップも更新)
5. マップを再生成し、NavMeshを再ベイクする
